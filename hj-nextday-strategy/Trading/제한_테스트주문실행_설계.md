# 제한 테스트 주문 실행 설계

## 0) 기준 시점 / 문서 목적
- 기준일: **2026-04-25 (UTC)**
- 이전 단계 근거:
  - `Trading/테스트주문실행여부_재재판단.md`
  - `Trading/허용유니버스_재정의.md`
- 목적:
  1. `allow_test` 후보에 한해서만 제한 테스트 주문 실행 조건 확정
  2. 금액/수량/횟수/동시 보유 제한값을 운영 가능 수준으로 고정
  3. 실제 주문 전, 승인 기준과 중단 기준을 먼저 확정

---

## 1) 제한 테스트 주문 대상 선정 기준 (확정)

### 1-1. 대상 종목 범위
- 이번 단계 대상은 **최대 2종목**으로 고정
- 기준 universe: `{A00001, D10004, P10001}`
- 실행 우선 대상:
  1. **A00001**
  2. **D10004**
- 예비 대상:
  - `P10001` (동시 보유/한도 여유가 있을 때만 재검토)

### 1-2. 후보 편입 필수 조건
아래를 모두 만족해야 `allow_test_candidate=true`:
1. `ticker ∈ {A00001, D10004}`
2. `market_phase=post_close`
3. `source_signal_type=post_close_confirmed`
4. `final_decision=pass`
5. `blocked_reason=[]` (빈 배열)
6. 게이트 상태 `status=pass`
7. 필수 로그/상태 저장 성공 (`state_write_ok=true`, `log_write_ok=true`)

### 1-3. 즉시 제외 조건
아래 중 하나라도 있으면 즉시 제외:
- `phase_not_post_close_confirmed`
- `final_decision_not_pass`
- `ticker_not_in_eligible_universe`
- `insufficient_liquidity`
- `industry_stage_4_or_5`
- `leader_alignment_broken`
- `foreign_flow_only_strong`
- `non_leader_stock_excluded`

---

## 2) 1회/1일 주문 제한값 (확정)

### 2-1. 1회 주문 제한
- **최소 주문 금액**: `100,000 KRW`
- **1회 최대 주문 금액**: `200,000 KRW`
- **최소 주문 수량**: `1주`
- **1회 최대 주문 수량**: `2주` (단, 1회 최대 금액 이내)
- 주문 방식: **지정가만 허용** (시장가 금지)

### 2-2. 1일 주문 제한
- **1일 최대 테스트 주문 횟수**: `1회`
- **종목별 1일 최대 테스트 금액**: `200,000 KRW`
- **전체 1일 최대 테스트 금액**: `200,000 KRW`
- 같은 날 다종목 분할 주문 금지 (운영 단순화 목적)

### 2-3. 승인 체계
- `auto_allow` 금지
- 당일 후보 1건 생성 후 아래 순서로 승인:
  1. 시스템 조건 충족 체크
  2. 운영자 수동 승인 (`human_approval=true`)
  3. 승인 이력 기록 후에만 실행 가능 상태로 전환

---

## 3) 동시 보유 / 재진입 제한 (확정)

### 3-1. 동시 보유 제한
- **동시 보유 가능 종목 수: 최대 1개**
- 기존 보유가 있으면 신규 테스트 주문 금지

### 3-2. 재진입 제한
- 동일 종목 **당일 재진입 금지**
- 체결 실패/취소 포함, 당일 재시도 금지
- 다음 영업일에만 재평가 가능

### 3-3. 포지션 충돌 방지
- 당일 테스트 포지션이 열려 있으면 다른 후보가 더 좋아도 추가 진입 금지
- 일관성 검증이 목적이므로 수익 기회보다 통제 우선

---

## 4) 주문 후 확인 체크리스트 (확정)

### 4-1. 체결 직후 체크 (T+0)
1. 체결 여부/체결가/수량 일치 확인
2. 주문 제한 준수 확인 (`<=200,000 KRW`, `1회`, `1종목`)
3. `blocked_reason` 사후 발생 여부 확인
4. 상태 저장/로그 저장 정상 여부 확인

### 4-2. 장 마감 후 체크 (T+0 close)
1. post_close 판단 근거와 실제 체결 로그 매칭
2. 슬리피지/미체결/지연 여부 기록
3. 신호 품질 메모 (`pass` 근거 재검증)
4. 다음 영업일 재진입 금지 플래그 반영 여부 확인

### 4-3. 일일 리포트 필수 항목
- `as_of`, `ticker`, `requested_amount`, `filled_amount`
- `decision_snapshot` (`phase`, `final_decision`, `blocked_reason`)
- `limit_snapshot` (`orders_today`, `amount_today`, `concurrent_positions`)
- `anomaly_detected` (true/false)
- `next_day_status` (`continue_test` / `hold_test` / `block_test`)

## 5) 중단 조건 / 재보류 조건 (확정)

### 5-1. 즉시 중단 (`block_test`) 조건
아래 중 하나라도 발생하면 즉시 중단:
1. post_close confirmed 조건 불일치 주문 시도
2. `final_decision != pass` 상태 주문 시도
3. 차단 플래그 존재 상태 주문 시도
4. 1회/1일 제한 위반 시도
5. 동시 보유 제한 위반 시도
6. 로그/상태 저장 실패
7. 이상 체결(지연, 비정상 가격, 중복 체결) 탐지

실행 규칙:
- 중단 즉시 `test_order_enabled=false`
- 당일 추가 실행 전면 금지
- 원인/재발방지 메모 기록 전까지 자동 복구 금지

### 5-2. 재보류 (`hold_test`) 조건
아래 중 하나면 다음 날부터 `hold_test` 전환:
1. 최근 3영업일 중 1회 이상 이상징후 발생
2. 후보 부족으로 강제 진입 유혹이 관측됨
3. 승인 절차 누락/지연
4. 리포트 누락
5. 운영자 검토에서 신호 일관성 저하 판단

### 5-3. 재개 조건 (`review_test` → 제한 실행)
아래 모두 충족 시에만 재개:
1. 최근 3영업일 이상 무이상 로그 확보
2. 승인 절차 100% 준수
3. 제한값 위반 0건
4. 운영자 재승인 완료

---

## 6) 이번 단계 완료 판정
아래 5개가 모두 충족되면 이번 단계 완료:
1. 제한 테스트 주문 실행 설계 문서 완료
2. 대상 종목 기준 확정 (`A00001`, `D10004`)
3. 금액/횟수/보유 제한 확정
4. 주문 후 체크리스트 확정
5. 중단/재보류 조건 확정

최종 상태 선언:
- **전면 오픈 금지 유지**
- **허용 후보 1~2종목 한정 제한 테스트 설계 확정**
- **실주문 실행은 다음 승인 단계에서 별도 개시**
