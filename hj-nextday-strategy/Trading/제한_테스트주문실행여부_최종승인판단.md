## 1) 최종 판단 프레임

### 1-1. 기술 통과 vs 운영 승인 분리
- 기술 통과(게이트): 현재 **pass**
- 운영 승인(실행 허용): 기술 통과와 별개로 **보수적으로 별도 판단**
- 원칙: 설계/게이트 통과가 있어도 운영 리스크가 남으면 `hold` 가능

### 1-2. 최종 상태 값 정의
- `approve_test`: 제한 테스트 주문 즉시 집행 가능 상태(수동 승인 포함)
- `hold_test`: 실행 보류, 추가 검증/재확인 필요
- `block_test`: 실행 금지(즉시 중단)
- `review_test`: 경계 사례, 수동 재심사 필요

## 2) 현 시점 최종 결론

## **결론: HOLD(보류) 유지 + 단일 축소안 조건부 승인 가능**

- 기본 운영 결론: **`hold_test` 유지**
- 보조 상태: **`review_test` 유지**
- 예외 승인: 아래 승인 조건을 모두 만족하는 경우에 한해 **`1종목 / 최소 금액 / 1회성` 제한 테스트 주문 1건만 조건부 승인 가능**
- 전제: 본 문서는 “실행 가능성 최종 승인 판단”이며, 즉시 자동 주문 개시는 아님

결론 해석:
1. 기술적 준비도는 확인됐으나, 운영 관점에서 보수적 통제가 계속 필요함.
2. 따라서 전면 승인(1~2종목 동시 확장)은 현재 시점에서 부적절.
3. 먼저 단일 축소안으로 통제 가능한지 확인 후, 다음 단계에서 확대 여부 재판단.

## 3) 승인 / 보류 / 차단 / 재검토 기준 (최종)

### 3-1. 승인(`approve_test`) 조건
아래를 **모두** 만족할 때만 조건부 승인:
1. 종목: `ticker ∈ {A00001, D10004}`
2. 신호: `market_phase=post_close`, `source_signal_type=post_close_confirmed`
3. 의사결정: `final_decision=pass`
4. 차단사유: `blocked_reason=[]` (완전 빈 배열)
5. 게이트: `status=pass` 유지
6. 저장성: `state_write_ok=true`, `log_write_ok=true`
7. 수동 승인: 승인자 1인 명시 + 승인 시각 기록 + 주문 전 최종 체크리스트 서명

### 3-2. 보류(`hold_test`) 사유
아래 중 하나라도 해당 시 보류:
1. 최근 3~5영업일 재현성 데이터 부족
2. 운영 승인 로그 누락/지연
3. 한도 규칙은 맞지만 경계 신호(정렬/수급 충돌) 비중 증가
4. 일일 리포트 누락 또는 사후 점검 미완료

### 3-3. 차단(`block_test`) 사유
아래 중 하나라도 발생 시 즉시 차단:
1. `phase_not_post_close_confirmed`
2. `final_decision_not_pass`
3. `ticker_not_in_eligible_universe`
4. `insufficient_liquidity`
5. `industry_stage_4_or_5`
6. `leader_alignment_broken`
7. `foreign_flow_only_strong`
8. `non_leader_stock_excluded`
9. 제한 위반: `requested_amount_exceeds_max_per_order`, `daily_*_exceeded`, `max_concurrent_positions_reached`
10. 로그/상태 저장 실패, 이상 체결(중복/비정상가/지연) 발생

### 3-4. 재검토(`review_test`) 사유
- 기술 기준은 통과했으나 운영 해석 충돌이 있는 경계 케이스
- 승인자는 재검토 메모(허용/보류 근거)를 남기고 당일 1회만 결론

## 4) 제한 테스트 주문 실행 범위 최종 확정

### 4-1. 기본 확정 범위
- **종목 수: 1종목만 허용** (이번 단계 최종 확정)
- **주문 횟수: 1일 1회**
- **주문 방식: 지정가만 허용**
- **동시 보유: 최대 1개**

### 4-2. 금액 축소안(최종)
- 최소 주문 금액: **100,000 KRW**
- 이번 단계 실행 상한(축소): **100,000 KRW (기존 200,000 KRW에서 축소 적용)**
- 즉, 첫 실행은 **“1종목 / 10만원 / 1회성”**만 허용

### 4-3. 후보 우선순위
1. `A00001` (우선)
2. `D10004` (대체)
- 동일 일자에는 한 종목만 선택 가능

## 5) 수동 승인 절차 재확인 (실행 직전 필수)
1. 시스템 조건 체크 (`post_close_confirmed`, `pass`, 무차단)
2. 한도 체크 (1종목/1회/10만원/동시보유 1)
3. 승인자 확인 (`human_approval=true`, 승인자 ID/시각 기록)
4. 주문 요청 전 최종 구두/문서 확인
5. 주문 후 즉시 체결/로그/상태 저장 확인

미충족 시 규칙:
- 한 항목이라도 실패하면 **즉시 `hold_test` 또는 `block_test`로 전환**
- 당일 추가 시도 금지

---

## 6) 즉시 중단 조건 재확인
아래 발생 시 즉시 중단:
1. 비정상 체결(지연/중복/허용범위 밖 가격)
2. 제한값 위반 시도 또는 위반 정황
3. 승인 누락 상태 주문 시도
4. 저장 실패(`state/log write fail`)

중단 후 처리:
- `test_order_enabled=false`
- 당일 전면 중지
- 원인/재발방지 문서 기록 전 재개 금지
