## 2) 테스트 주문 실행 판단 상태 정의 (운영 기준)

- `allow_test`: 제한 조건 내 테스트 주문 즉시 허용
- `hold_test`: 조건 미흡으로 보류
- `block_test`: 현재 금지(자동/운영 차단)
- `review_test`: 일부 조건 충족, 보완 후 재검토

운영 적용 원칙:
- 기술 검증 통과(`gate pass`)와 운영 승인(`allow_test`)은 분리한다.

## 3) 이번 재판단 결론

## **결론: review_test (조건부 재검토) + 기본 운영은 hold_test 유지**

사유:
1. 기술 게이트는 `status=pass`, `live_order_connection_allowed=true`로 통과.
2. 그러나 dry-run에서 실제 허용은 1/13으로 매우 제한적이며, 운영 데이터 축적이 아직 부족.
3. 차단 사유가 주로 구조적(유니버스/결정 미통과)이라 “시스템이 안전하게 막고 있음”은 확인됐지만,
   “허용 케이스의 안정적 반복성”은 아직 충분히 증명되지 않음.
4. 따라서 전면 오픈은 불가, 제한 테스트는 **추가 가드 조건 충족 시에만** 재검토.

상태 매핑:
- 오늘 즉시 집행 상태: `hold_test`
- 단계 레이블: `review_test`
- 금지 구간: `block_test` 조건은 계속 유효

## 4) allow_test 허용 조건 (필수 동시 충족)

아래를 **모두** 만족할 때만 `allow_test=true` 가능:

1. `market_phase = post_close`
2. `source_signal_type = post_close_confirmed`
3. `final_decision = pass`
4. gate 통과 상태 유지 (`pre_live_order_gate_report.status=pass`)
5. 차단 플래그 없음 (`blocked_reason` 비어있음)
6. `ticker`가 `eligible_tickers`에 포함
7. 금액/수량/횟수 한도 동시 충족
   - 1회 최대 300,000 KRW
   - 종목당 1일 최대 300,000 KRW
   - 전체 1일 최대 600,000 KRW
   - 1일 최대 2회
   - 동시 보유 최대 2종목
8. 로그/리포트 정상
   - dry-run 로그 기록 성공
   - ORDER API 미호출 상태 확인

## 5) hold_test / block_test 사유 정리

### 5-1. hold_test 사유
- 운영 검증 누적 부족(허용 케이스 표본 적음)
- 노이즈성 케이스 완전 소거 여부 추가 관찰 필요
- 수동 확인 필요 항목 존재(경계선 score/정렬 불일치 계열)

### 5-2. block_test 사유
- `final_decision_not_pass`
- `phase_not_post_close_confirmed`
- `industry_stage_4_or_5`
- `leader_alignment_broken`
- `foreign_flow_only_strong`
- 한도 초과 (`requested_amount_exceeds_max_per_order`, `daily_total_amount_limit_exceeded`, `daily_ticker_amount_limit_exceeded`)
- 유니버스 외 종목 (`ticker_not_in_eligible_universe`)

운영 원칙:
- `block_test` 사유가 1개라도 존재하면 자동 금지.

## 6) 제한된 테스트 주문 실행 범위 초안

### 6-1. 허용 가능 종목 수
- 기본: **일 1종목**
- 예외: 검증 로그가 5영업일 연속 안정일 때만 최대 2종목

### 6-2. 1회 최대 주문 금액
- 기본: **200,000 KRW** (현재 시스템 상한 300,000 대비 추가 보수)

### 6-3. 1일 최대 횟수
- 기본: **1회/일**
- 예외 완화 전까지 2회 설정은 비상/실험 슬롯으로만 보류

### 6-4. 주문 가능한 phase
- `post_close_confirmed` 기반 케이스만 허용
- `intraday_temporary` 기반 신규 테스트 주문 금지

### 6-5. 주문 후 반드시 확인할 항목
1. 체결 시간/슬리피지
2. 신호-주문 매핑 정합성(티커, 방향, 수량)
3. 리스크 한도 차감 반영 정확성
4. 로그/상태 저장 성공 여부
5. 익일 재현성(동일 규칙 재평가 일치 여부)
