# 자동주문 직전 검증 체계 준비

## 1) 목적
- 실주문 API 연결 전 마지막 안전장치를 문서/코드 기준으로 동시에 고정한다.
- 이번 단계에서는 **실주문 호출 자체를 금지**하고, 허용 조건과 차단 조건만 명확히 한다.

---

## 2) 자동주문 직전 체크리스트(필수 통과)
아래 항목은 `Trading/validate_pre_live_order_gate.py`에서 자동 검증한다.

1. **phase 분리 정상**
   - `market_phase`는 `intraday` 또는 `post_close`만 허용
   - `source_signal_type`은 `intraday_temporary` 또는 `post_close_confirmed`만 허용
   - `intraday ↔ post_close` 매핑 불일치 시 즉시 실패
2. **필수 필드 존재**
   - 결과 레코드에 필수 키 전부 존재
3. **final_decision 존재/유효성**
   - `pass|hold|block|review` 중 하나
4. **decision_reason / decision_flags 존재**
   - 빈 값 금지, 사람이 원인 확인 가능해야 함
5. **bridge 포맷 정상**
   - `INTRADAY_SIGNAL_BRIDGE.json`, `INTEGRATED_SIGNAL_BOARD.json` 최소 구조/phase 검증
6. **dry-run 결과 정상**
   - `dry_run_results.json`에 결과 존재
   - decision 분포가 최소 검증 조건 충족
7. **ORDER_API_CALLED=false 유지**
   - 결과 JSON의 `order_api_called`는 반드시 `false`
   - `dry_run.log`에 `ORDER_API_CALLED=false` 문자열 존재
8. **로그 출력 정상**
   - `dry_run.log`가 비어있지 않고 결과 행 포함

---

## 3) 실주문 허용 조건(문서 기준)
아래 조건을 **모두** 만족할 때만 향후 실주문 연결 검토 가능:

1. `market_phase == post_close`
2. `source_signal_type == post_close_confirmed`
3. `final_decision == pass`
4. 차단 플래그 없음
   - `INDUSTRY_STAGE_HIGH`
   - `FOREIGN_FLOW_ONLY_STRONG`
   - `LEADER_ALIGNMENT_BROKEN`
   - `PHASE_INCONSISTENT`
   - `REQUIRED_FIELDS_INCOMPLETE`
   - `INTRADAY_NOISE`
5. 필수 필드 완전
6. 리스크 조건 충족
   - `industry_stage < 4`
   - `leader_follower_alignment == aligned`
7. 테스트 통과
   - dry-run 및 pre-live gate 검증 스크립트 모두 성공

> 주의: 본 단계에서는 허용 조건을 정의만 하며, 실제 주문 API는 아직 비활성 상태를 유지한다.

---

## 4) 자동 차단 조건 재확인
다음 중 하나라도 참이면 자동주문 차단:

- `industry_stage` 고단계(4 이상)
- `foreign_flow_signal == foreign_only_strong`
- `leader_follower_alignment == broken`
- phase 충돌(phase/source 타입 불일치)
- 필수 필드 누락
- 로그/상태/결과 저장 실패
- 주문 API 비활성 가드 불일치(`ORDER_API_CALLED=false` 미확인)

---

## 5) 코드 기준과 문서 기준의 일치 방식
- 문서 기준: 본 문서의 체크리스트/허용조건/차단조건
- 코드 기준: `Trading/validate_pre_live_order_gate.py`
- 운영 기준: **문서+코드 동시 통과 전에는 자동주문 연결 금지**

---

## 6) 아직 부족한 점(실주문 전 남은 리스크)
1. 브로커 API 장애/지연 시 복구 시나리오 미확정
2. 주문 거절/부분 체결/재시도 정책 미정
3. 장시작 직후 급변 구간의 안전지연(쿨다운) 정책 미정
4. 승인 책임자/승인 로그 체계(수동 승인 프로세스) 미완성

---

## 7) 사람이 수동으로 봐야 할 항목
1. `decision_reason`의 설명 품질(실제 시장 근거와 일치 여부)
2. `review` 케이스 수동 승인/반려 기록
3. 당일 매크로 이벤트(FOMC, CPI 등)와 규칙 예외 필요성
4. dry-run 상 `pass` 케이스의 과최적화 여부(최근 성능 착시)

---
