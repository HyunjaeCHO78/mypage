# 제한테스트주문 실행트리거 최종승인

- 문서 목적: 제한 테스트 주문의 **최종 트리거 승인 여부**를 확정하고, 실행/금지/사후 의무를 마지막으로 고정한다.
- 작성일: 2026-04-26
- 기준 플래그: `test_order_enabled=false`
- 적용 범위: 제한 테스트 주문 1회성 실행 판단

---

## 1) test_order_enabled 전환 조건 (최종 확정)

아래 6개 조건을 **동시에 100% 충족**할 때만 `test_order_enabled=true` 전환 검토 가능.

1. **2인 승인 완료**
   - 1차 승인(전략) + 2차 승인(리스크) 모두 완료
   - 승인자/시각/근거 링크/승인 문구 누락 0건
2. **증빙 유효성 100%**
   - 체크리스트/승인로그/주문 파라미터/플래그 감사로그/모니터링 채널 모두 열람 가능
   - 권한 오류, 링크 만료, 타임스탬프 불일치 0건
3. **실행 전 게이트 통과**
   - `market_phase=post_close`
   - `source_signal_type=post_close_confirmed`
   - `final_decision=pass`
   - `blocked_reason=[]`
4. **제한 조건 사전 고정**
   - 1종목 / 1회 / 100,000 KRW / 지정가 / 동시보유 1개
5. **운영 저장성 정상**
   - `state_write_ok=true`
   - `log_write_ok=true`
6. **이상 징후 0건**
   - 중복주문/비정상가/지연체결/승인불일치/제한위반 시도 없음

> 원칙: 상기 조건 중 하나라도 미충족이면 `test_order_enabled`는 **반드시 false 유지**.

---

## 2) 실행 트리거 최종 결론 (고정)

### 최종 결론: **보류(HOLD) 유지**

- 이번 단계의 확정 상태는 `hold_test`.
- 즉시 자동 전환 승인하지 않는다.
- 단, 1장(전환 조건) 6개 항목이 실행 직전 재점검에서 전부 충족되면, 승인 콜 직후 **단발성 예외 승인**으로만 전환 가능.

상태 정의:
- 승인(Approve): 실행 직전 재검증 100% 충족 + 2인 최종 승인 콜 완료 시에만 허용
- 보류(Hold): 기본 상태, 현재 확정값
- 차단(Block): 금지조건 1건 발생 시 즉시 전환
- 재검토(Review): 신호/운영 해석 충돌 시 당일 1회 재심

---

## 3) 마지막 금지 조건 (최종 확정)

아래 항목 발생 시 실행 금지(즉시 `block_test` 또는 `hold_test` 복귀):

1. 2인 승인 미완료 또는 승인 로그 불완전
2. 증빙 링크 무효(권한 오류/만료/불일치)
3. `post_close_confirmed` 불충족
4. `final_decision!=pass`
5. `blocked_reason` 비어있지 않음
6. 허용 유니버스 외 종목 요청
7. 10만원 초과 또는 1일 1회 초과 요청
8. 지정가 외 주문 유형 요청
9. 동시보유 1개 초과 상태
10. 상태/로그 저장 실패
11. 이상 체결(중복, 허용범위 밖 가격, 비정상 지연)
12. 실행 중 이상 징후 발생 후 중단 미이행

---

## 4) 실행 직후 모니터링/리포트 의무 (재확정)

실행이 이루어진 경우 아래를 의무로 수행한다.

1. **즉시 모니터링**
   - 주문 접수~체결/취소까지 실시간 감시
   - 이상 징후 탐지 시 즉시 중단 + `test_order_enabled=false` 복귀
2. **30분 이내 1차 리포트**
   - 주문접수시각, 체결/취소시각, 체결수량, 평균체결가, 슬리피지, 이상여부
3. **당일 최종 리포트**
   - 정책 준수(1종목/1회/10만원/지정가) 체크
   - 예외/사고 여부, 재발방지 액션, 다음날 권고상태(approve/hold/block/review)
4. **추가 시도 제한**
   - 이상 징후 1건이라도 있으면 당일 추가 시도 금지

## 5) 다음 행동 확정
