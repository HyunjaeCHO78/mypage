# 최종승인 증빙양식 및 2인 승인로그 확정

## 0) 기준 시점 / 목적
- 기준 시점: **2026-04-25 (UTC)**
- 전제 상태: **`hold_test` 유지**, `test_order_enabled=false` 유지
- 목적:
  1. 실행 직전 최종 승인 체크리스트 증빙 양식 고정
  2. 1차/2차 승인 로그 포맷(서명/타임스탬프/증적 링크) 확정
  3. 주문 후 리포트 연결 포맷 확정
  4. 실행 전 문서적/운영적 요건 완전 충족

## 1) 최종 승인 체크리스트 증빙 양식 (고정본)

아래 양식은 실행 시마다 **동일 구조**로 작성한다. 필수 항목 누락 시 즉시 실행 금지.

### 1-1. 문서 메타
- `doc_id`: `FINAL-APPROVAL-YYYYMMDD-<ticker>-<seq>`
- `created_at_utc`: ISO8601 UTC
- `trade_date_local`: YYYY-MM-DD (Asia/Seoul)
- `owner_team`: Trading Ops
- `status`: `draft | ready_for_approval | approved | rejected | archived`

### 1-2. 실행 전 체크 (증빙 필수)
1. **신호/결정 증빙**
   - `market_phase=post_close`
   - `source_signal_type=post_close_confirmed`
   - `final_decision=pass`
   - `blocked_reason=[]`
   - 증빙 링크: `evidence.signal_snapshot_url`
2. **한도/리스크 증빙**
   - 대상: 1종목
   - 횟수: 1일 1회
   - 금액: 100,000 KRW
   - 동시보유: 최대 1
   - 증빙 링크: `evidence.limit_snapshot_url`
3. **시스템/로그 건강성 증빙**
   - `gate_status=pass`
   - `state_write_ok=true`
   - `log_write_ok=true`
   - 증빙 링크: `evidence.pre_live_gate_report_url`
4. **운영 절차 증빙**
   - 브리핑 완료
   - 예외/이상 징후 없음 확인
   - 2인 승인 완료 전까지 `test_order_enabled=false`
   - 증빙 링크: `evidence.ops_briefing_note_url`

### 1-3. 체크리스트 판정 규칙
- 판정 값: `PASS | FAIL | N/A(허용불가)`
- 실행 가능 조건:
  - 모든 필수 항목 `PASS`
  - 1차/2차 승인 상태 `APPROVED`
  - `test_order_enabled` 전환 승인 이벤트 존재
- 한 항목이라도 `FAIL`이면 최종 상태 `HOLD` 또는 `BLOCK`

## 2) 2인 승인 로그 포맷 확정

## 2-1. 공통 로그 레코드 스키마 (JSON Lines 권장)
```json
{
  "approval_id": "APR-20260425-A00001-001",
  "doc_id": "FINAL-APPROVAL-20260425-A00001-001",
  "approval_stage": "L1",
  "approver_id": "trader_01",
  "approver_role": "Primary Approver",
  "decision": "APPROVED",
  "decision_reason": "체크리스트 100% PASS, 차단사유 없음",
  "signature_type": "electronic",
  "signature_hash": "sha256:...",
  "signed_at_utc": "2026-04-25T09:10:00Z",
  "evidence_links": {
    "checklist": "...",
    "signal_snapshot": "...",
    "limit_snapshot": "...",
    "pre_live_gate_report": "..."
  },
  "timestamp_server": "ops-audit-01",
  "log_integrity_hash": "sha256:...",
  "created_at_utc": "2026-04-25T09:10:02Z"
}
```

### 2-2. 1차 승인(L1) 필수 항목
- 책임: 실행 조건의 **기술/한도 충족 검증**
- 필수 필드:
  - `approval_stage=L1`
  - `decision` (`APPROVED | REJECTED | HOLD`)
  - `signed_at_utc`
  - `signature_hash`
  - 핵심 증빙 링크 4종

### 2-3. 2차 승인(L2) 필수 항목
- 책임: 실행 조건의 **운영 리스크 최종 수용 여부 판단**
- 필수 필드:
  - `approval_stage=L2`
  - `decision` (`APPROVED | REJECTED | HOLD`)
  - `signed_at_utc`
  - `signature_hash`
  - `l1_reference_approval_id` (L1 승인 로그 참조)
  - `final_go_no_go` (`GO | NO_GO`)

### 2-4. 승인 순서/유효성 규칙
1. L1 승인 없이 L2 승인 불가
2. L1/L2 승인자는 **서로 다른 사용자 ID**여야 함
3. `signed_at_utc(L2) >= signed_at_utc(L1)`
4. L2의 `final_go_no_go=GO` 전에는 `test_order_enabled=false` 유지
5. 로그 무결성 해시 누락 시 승인 무효

## 3) 서명 / 타임스탬프 / 증적 링크 필드 확정

### 3-1. 서명 필드
- `signature_type`: `electronic` 고정
- `signature_hash`: 전자서명 원문 해시 (sha256)
- `signature_scope`: 서명 대상 범위 (`doc_id`, `approval_id`, `decision_payload_hash`)

### 3-2. 타임스탬프 필드
- `signed_at_utc`: 승인자가 서명 완료한 시점
- `created_at_utc`: 로그 레코드 생성 시점
- `ingested_at_utc`: 중앙 감사 로그 수집 시점
- 시간 기준: 모두 UTC ISO8601

### 3-3. 증적 링크 필드 (필수 6종)
1. `checklist_url`
2. `signal_snapshot_url`
3. `limit_snapshot_url`
4. `pre_live_gate_report_url`
5. `risk_note_url`
6. `ops_briefing_note_url`

링크 정책:
- 사내 접근 권한 통제 URL만 허용
- 만료성 URL 금지(감사 시점 접근 가능해야 함)
- 파일 변경 시 버전 ID 포함 필수

## 4) 주문 후 리포트 연결 포맷(초안 확정)

### 4-1. 연결 키
- `doc_id` (체크리스트 문서)
- `approval_id_l1`, `approval_id_l2` (승인 로그)
- `order_request_id`, `order_execution_id` (주문/체결)
- `post_trade_report_id` (사후 리포트)

### 4-2. 최소 매핑 구조
```json
{
  "doc_id": "FINAL-APPROVAL-20260425-A00001-001",
  "approval": {
    "l1": "APR-20260425-A00001-001-L1",
    "l2": "APR-20260425-A00001-001-L2"
  },
  "order": {
    "order_request_id": "REQ-...",
    "order_execution_id": "EXE-..."
  },
  "post_trade_report_id": "PTR-20260425-A00001-001",
  "final_outcome": "NORMAL | ANOMALY | BLOCKED"
}
```

### 4-3. 사후 감사 조회 키
- 1차 키: `doc_id`
- 2차 키: `trade_date_local + ticker`
- 3차 키: `approval_id`

## 5) 실행 전 마지막 문서/운영 요건 체크

아래 8개를 모두 충족해야 실행 검토 단계로 이동 가능.

1. 최종 체크리스트 문서 `status=ready_for_approval`
2. 필수 증빙 링크 6종 첨부 완료
3. L1 승인 로그 작성 및 서명 완료
4. L2 승인 로그 작성 및 서명 완료
5. L1/L2 승인자 분리 검증 완료
6. 중앙 감사 저장소 적재 확인 (`ingested_at_utc` 기록)
7. 주문 후 리포트 연결 키 사전 발급 완료
8. 승인 완료 이벤트 전까지 `test_order_enabled=false` 유지 확인

판정:
- 8개 중 하나라도 미충족 시 **실행 금지**
- 모두 충족 시에도 당일 이상징후 재검토 후 최종 GO/NO_GO 선언

## 6) 다음 행동 (명확화)
1. 본 문서 양식으로 `FINAL-APPROVAL` 템플릿 파일 1건 생성
2. L1/L2 승인자 지정(서로 다른 ID) 및 오늘자 모의 로그 1세트 기록
3. 증빙 링크 6종 실제 경로 매핑 점검
4. 주문 후 리포트 매핑 키(`doc_id`, `approval_id`, `post_trade_report_id`) 사전 생성
5. 위 1~4 완료 전까지 `test_order_enabled=false` 유지

최종 선언:
- **증빙 미첨부 시 실행 금지**
- **2인 승인 미완료 시 실행 금지**
- **승인 로그는 추후 감사/리뷰 가능 형식으로 영구 보관**
- **현재 상태는 HOLD(재검토 필요) 유지**
