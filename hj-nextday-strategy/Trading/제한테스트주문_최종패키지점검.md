# 제한 테스트 주문 최종 패키지 점검서 (실행 직전 리허설)

- 문서 목적: 실제 제한 테스트 주문 실행 직전, 승인 패키지(체크리스트/1차 승인/2차 승인/증빙/주문 후 리포트 초안)의 연결성과 누락 여부를 최종 점검한다.
- 작성일: 2026-04-26
- 상태 기준: **누락 1건이라도 발견 시 실행 금지(HOLD)**
- 시스템 플래그: `test_order_enabled=false` 유지 (수동 최종 승인 완료 전 변경 금지)

---

## 1) 최종 패키지 구성요소 점검 (원패키지 연결 확인)

아래 5개 묶음이 하나의 실행 패키지로 연결되어 있어야 한다.

1. 실행 체크리스트 최종본
2. 1차 승인 로그(전략 담당)
3. 2차 승인 로그(리스크 담당)
4. 증빙 링크 묶음(문서/로그/스냅샷)
5. 주문 후 리포트 초안

### 패키지 인덱스 표

| 구분 | 필수 문서/로그 | 현재 상태 | 링크/위치 | 누락 여부 |
|---|---|---|---|---|
| 체크리스트 | 제한 테스트 주문 실행 체크리스트 최종본 | 확인 완료 | (링크 입력) | 없음 |
| 1차 승인 | 1차 승인 시각/승인자/승인문구/서명 | 확인 필요 | (링크 입력) | 점검 필요 |
| 2차 승인 | 2차 승인 시각/승인자/승인문구/서명 | 확인 필요 | (링크 입력) | 점검 필요 |
| 증빙 묶음 | 주문 파라미터 캡처, 로그, 타임스탬프 | 확인 필요 | (링크 입력) | 점검 필요 |
| 사후 리포트 초안 | 주문 후 리포트 템플릿 + 필수 필드 | 확인 완료 | (링크 입력) | 없음 |

---

## 2) 빈칸/누락 항목 점검 결과

실행 직전 리허설 관점에서, 아래 빈칸은 모두 실제 값으로 채워져야 한다.

### 필수 입력 필드

- 거래일: `YYYY-MM-DD`
- 종목명/종목코드: `________ / ________`
- 주문 유형: `지정가`
- 주문 수량/총액: `________ / 100,000원 이내`
- 매수 지정가/허용 괴리: `________ / ________`
- 주문 유효시간/취소 시각: `HH:MM ~ HH:MM / HH:MM`
- 실행자/모니터링 담당/비상 중단 담당: `________ / ________ / ________`

### 누락 판단 규칙

- 위 필드 중 1개라도 공란이면 상태를 즉시 `HOLD`로 유지한다.
- 승인 로그(1차/2차) 중 한 단계라도 누락되면 실행 금지.
- 증빙 링크가 클릭 불가/권한 없음/타임스탬프 불일치이면 실행 금지.

---

## 3) 1차/2차 승인 흐름 연결 점검

승인 단계는 반드시 순차적으로 이어져야 하며, 역순/동시 승인/구두 승인 단독 처리 금지.

### 승인 흐름

1. 체크리스트 완료 확인
2. 1차 승인(전략 담당) 기록
3. 2차 승인(리스크 담당) 기록
4. 최종 실행 직전 재확인(실행자)
5. `test_order_enabled=true` 전환 가능 여부 검토

### 승인 로그 필수 항목

- 승인 단계: 1차 / 2차
- 승인 시각(로컬시간): `YYYY-MM-DD HH:MM:SS`
- 승인자 실명/역할
- 승인 문구(고정)
- 승인 근거 링크(체크리스트/증빙)
- 변경 이력(수정 시각/수정자)

> 고정 승인 문구 예시: "제한 테스트 주문 실행 조건(1종목/1회/지정가/한도 준수) 확인 완료. 실행 직전 단계 승인."

---

## 4) 주문 후 리포트 초안 연결 점검

주문은 아직 실행하지 않더라도, 리포트 초안은 승인 패키지에 선연결되어 있어야 한다.

### 리포트 초안 필수 섹션

- 주문 개요(거래일/종목/의도/조건)
- 체결 결과(요청가/체결가/슬리피지/미체결)
- 정책 준수 점검(한도/횟수/종목수/주문방식)
- 이슈 및 예외(발생 여부/대응)
- 결론(재실행 권고: 승인/보류/차단)

### 연결 확인 기준

- 승인 패키지에서 리포트 초안 링크를 한 번에 열 수 있어야 함
- 리포트 초안의 식별자(거래일/종목/실행ID)가 승인 로그와 동일해야 함
- 리포트 담당자 및 작성 시점 SLA가 사전 기재되어 있어야 함

---

## 5) 실행 직전 최종 누락 리스트 (작성본)

아래 항목은 실제 실행 직전 반드시 `해소 완료`로 변경되어야 한다.

| No | 누락/확인 필요 항목 | 현재 상태 | 해소 기준 | 담당 |
|---|---|---|---|---|
| 1 | 1차 승인 로그 실서명/시각 입력 | 미완료 | 승인 로그 필수 항목 100% 기입 | 전략 담당 |
| 2 | 2차 승인 로그 실서명/시각 입력 | 미완료 | 승인 로그 필수 항목 100% 기입 | 리스크 담당 |
| 3 | 증빙 링크 유효성(권한/열람/타임스탬프) | 미완료 | 샘플 점검 3건 모두 정상 열람 | 운영 담당 |
| 4 | 실행 파라미터 빈칸 제거 | 미완료 | 필수 입력 필드 공란 0건 | 실행자 |
| 5 | test_order_enabled 재확인 | 완료 | 승인 전 false 유지 로그 확인 | 실행자 |

---

## 6) 실행 전 준비 상태 재확인 결론

- 현재 결론: **실행 대기(HOLD 유지)**
- 사유: 승인 로그(1차/2차) 실기입 및 증빙 링크 유효성 검증이 아직 미완료.
- 통제 상태: `test_order_enabled=false` 유지 중.
- 실행 가능 전환 조건: 누락 리스트 1~4번이 모두 해소되고, 2인 수동 승인 완료 후 최종 재확인 통과.

---

## 7) 다음 행동 (명확화)

1. 1차 승인 로그 실기입 및 서명 완료
2. 2차 승인 로그 실기입 및 서명 완료
3. 증빙 링크 유효성 점검 체크(열람/권한/타임스탬프)
4. 실행 파라미터 공란 0건 확인
5. 최종 5분 리허설 후에만 실행 스위치 검토

> 실행 원칙 재확인: **누락 1건이라도 있으면 실행하지 않는다. 수동 승인 완료 전까지 `test_order_enabled=false`를 유지한다.**
