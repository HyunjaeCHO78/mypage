# 피보나치 전략 PineScript 구현 명세서 (Implementation Spec v1.0)

- 작업명: `Trading/피보나치전략파인스크립트명세`
- 기준 문서: `Trading/피보나치전략백테스트설계서.md`
- 목적: 백테스트 설계 규칙을 PineScript 전략 코드로 즉시 구현 가능한 형태로 고정한다.
- 적용 범위: TradingView `strategy()` 기반 자동 백테스트/시각화 코드

---

## 1) PineScript 전략 구조

## 1.1 `strategy()` 선언 방향
- 스크립트 타입: `strategy()`
- 기본 모드: **롱/숏 양방향 지원**
- 기본 설정 권장값
  - `overlay=true`
  - `pyramiding=0` (중복 진입 금지)
  - `initial_capital` / `commission_type` / `commission_value` 명시
  - `process_orders_on_close=true` (리페인트/체결 시점 불일치 완화)
  - `calc_on_order_fills=true`

## 1.2 롱/숏 분리 구조
- 내부 로직은 동일 템플릿, 방향만 분리
  - Long 흐름: 상승 추세 + 하락 되돌림 + 반등 트리거
  - Short 흐름: 하락 추세 + 상승 되돌림 + 재하락 트리거
- 코드 레벨 분리 원칙
  - `canLong`, `canShort` boolean 별도 유지
  - `strategy.entry("L", strategy.long)` / `strategy.entry("S", strategy.short)` 개별 호출
  - 청산도 `from_entry`를 L/S로 분리

## 1.3 상위 추세 필터 / 진입 / 청산 파이프라인
- 단계 고정:
  1. **추세 필터**(4H 기반)
  2. **스윙 포인트 확정**(1H pivot/fractal)
  3. **피보나치 레벨 계산**
  4. **진입 트리거 확인**
  5. **리스크 검증(RR/제외조건)**
  6. `strategy.entry`
  7. `strategy.exit`(SL/TP1/TP2/Trailing)

## 2) 입력 변수(input) 목록

아래는 PineScript `input.*`로 구현하는 기본 세트다.

## 2.1 추세/구조 입력
- `emaFastLen` (int, 기본 50)
- `emaSlowLen` (int, 기본 200)
- `adxLen` (int, 기본 14)
- `adxMin` (float, 기본 18~25 범위 최적화)
- `pivotLeft` (int, 기본 3)
- `pivotRight` (int, 기본 3)
- `useFractal` (bool, 기본 false; true면 fractal 방식 사용)

## 2.2 피보나치 입력
- `fibAnchorMode` (string)
  - 옵션: `"RecentSwing"`, `"LastConfirmedAB"`
- `fibEntryMain` (float, 기본 0.5)
- `fibEntryAlt` (float, 기본 0.618)
- `goldenLow` (float, 기본 0.5)
- `goldenHigh` (float, 기본 0.618)
- `entryTolerancePct` (float, 기본 0.1~0.3%)

## 2.3 손절/익절 입력
- `slAtrLen` (int, 기본 14)
- `slAtrMult` (float, 기본 1.0~1.8)
- `tp1RR` (float, 기본 1.0)
- `tp2RR` (float, 기본 2.0)
- `tp1QtyPct` (float, 기본 50)
- `useTrailing` (bool, 기본 true)
- `trailAfterTP1` (bool, 기본 true)
- `trailAtrMult` (float, 기본 1.0~2.0)
- `closeOnOppSignal` (bool, 기본 true)

## 2.4 필터 입력
- `useSessionFilter` (bool, 기본 true)
- `sessionStr` (session, 예: `"0900-2300"` 또는 거래소 기준 세션)
- `useVolumeFilter` (bool, 기본 true)
- `volMaLen` (int, 기본 20)
- `volMinRatio` (float, 기본 1.1; 현재 거래량 >= 거래량MA×비율)
- `useRangeFilter` (bool, 기본 true)
- `atrRangeLen` (int, 기본 14)
- `minAtrPct` (float, 기본 0.4~0.8)

## 2.5 제외/안전장치 입력
- `minRR` (float, 기본 1.5)
- `maxBarsSincePivot` (int, 기본 40)
- `cooldownBars` (int, 기본 5)
- `avoidEventWindow` (bool, 기본 false; Pine 단독으론 수동 세션 우회로 처리)
- `eventSessionStr` (session, 예: `"1230-1330"`)

## 3) 진입 조건의 코드화 방식

## 3.1 추세 조건 boolean
- Long 추세
  - `emaFast > emaSlow`
  - `adx >= adxMin`
  - 필요 시 `close > emaFast` 추가
- Short 추세
  - `emaFast < emaSlow`
  - `adx >= adxMin`
  - 필요 시 `close < emaFast` 추가

```pine
trendLong  = emaFast > emaSlow and adxVal >= adxMin
trendShort = emaFast < emaSlow and adxVal >= adxMin
```

## 3.2 스윙 포인트 탐지 방식
- 기본: `ta.pivothigh`, `ta.pivotlow` 사용
- 확정된 pivot만 사용(미확정 고점/저점 금지)
- 최근 스윙 2개로 A-B 구간 정의
  - Long: 저점(A) → 고점(B) 이후 되돌림
  - Short: 고점(A) → 저점(B) 이후 되돌림
- 유효성
  - `bar_index - pivotBar <= maxBarsSincePivot`
  - 스윙 폭이 최소 ATR 배수 이상인지 확인

## 3.3 피보나치 레벨 계산 방식
- Long (상승파 되돌림)
  - `range = B - A`
  - `fib50 = B - range * 0.5`
  - `fib618 = B - range * 0.618`
- Short (하락파 되돌림)
  - `range = A - B`
  - `fib50 = B + range * 0.5`
  - `fib618 = B + range * 0.618`
- 골드존
  - `goldenLowPrice = min(fib50, fib618)`
  - `goldenHighPrice = max(fib50, fib618)`

## 3.4 진입 트리거 발생 조건
- 공통 전제: 추세 true + 스윙 유효 + 제외조건 false
- Long 트리거 예시
  1. 가격이 골드존 터치 (`low <= goldenHighPrice and high >= goldenLowPrice`)
  2. 반등 확인 (`close > open` 또는 `ta.crossover(close, fibEntryMainPrice)`)
  3. 거래량 필터 통과
- Short 트리거 예시
  1. 가격이 골드존 터치
  2. 재하락 확인 (`close < open` 또는 `ta.crossunder(close, fibEntryMainPrice)`)
  3. 거래량 필터 통과

```pine
longTrigger = trendLong and inGoldenZoneLong and reboundSignal and volPass and baseFiltersPass
shortTrigger = trendShort and inGoldenZoneShort and breakdownSignal and volPass and baseFiltersPass
```

## 4) 청산 조건의 코드화 방식

## 4.1 손절(SL)
- 기준: 최근 스윙 이탈 + ATR 버퍼
- Long
  - `stopL = swingLow - atr * slAtrMult`
- Short
  - `stopS = swingHigh + atr * slAtrMult`
- `strategy.exit`에서 `stop=` 사용

## 4.2 1차 익절(TP1)
- RR 기반 고정
- Long: `tp1 = entry + (entry - stopL) * tp1RR`
- Short: `tp1 = entry - (stopS - entry) * tp1RR`
- 수량: `qty_percent = tp1QtyPct`

## 4.3 2차 익절(TP2)
- RR 기반 고정
- Long: `tp2 = entry + (entry - stopL) * tp2RR`
- Short: `tp2 = entry - (stopS - entry) * tp2RR`
- 잔여 물량 청산 대상

## 4.4 트레일링 여부
- `useTrailing=true`일 때만 적용
- 권장 방식
  - TP1 체결 전: 고정 SL 유지
  - TP1 체결 후: BE(진입가) 또는 ATR 트레일로 전환
- Pine 구현
  - `strategy.exit`를 분리(`L-TP1`, `L-TP2`)하고 TP2쪽에 trail 로직 적용

## 4.5 반대 시그널 청산 여부
- `closeOnOppSignal=true`이면
  - Long 보유 중 `shortTrigger` 발생 시 `strategy.close("L")`
  - Short 보유 중 `longTrigger` 발생 시 `strategy.close("S")`
- 우선순위: 강제 반대 청산 > 일반 TP2

## 5) 제외 조건의 코드화 방식

## 5.1 횡보장 제외
- 조건 예시
  - `adx < adxMin` 또는 `atrPct < minAtrPct`
- 구현
```pine
sidewayFilter = adxVal < adxMin or atrPct < minAtrPct
```

## 5.2 RR 미달 제외
- 진입 전 예상 RR 계산
  - `rrToTp2 = abs(tp2-entry) / abs(entry-stop)`
- `rrToTp2 < minRR`면 진입 금지

## 5.3 이벤트 시간 제외
- Pine 단독으로 외부 경제지표 캘린더 자동 연동이 제한되므로,
  - 수동 세션 기반 제외(`eventSessionStr`)로 구현
  - 이벤트 전후 30~60분 회피를 세션 문자열로 입력

## 5.4 기준점 불명확 제외
- 다음 중 하나면 제외
  - pivot 미확정
  - A/B 스윙 순서 역전
  - 스윙 폭이 최소값 미달
  - pivot 발생 후 경과 bars 초과

## 6) 백테스트 출력 항목

## 6.1 진입/청산 표시
- `plotshape(longTrigger/shortTrigger)`로 진입 시그널 표시
- 실제 체결은 `strategy.opentrades` 또는 `strategy.position_size` 조건으로 라벨 표시
- `plotshape` 또는 `label.new`로 TP1/TP2/SL 체결 마커 표시

## 6.2 피보나치 레벨 표시
- `line.new` 또는 `plot`으로 0.5, 0.618, 스윙 A/B 표시
- 현재 유효 스윙 구간만 표시(오래된 라인 삭제/갱신)

## 6.3 A/B/C 등급 표시 가능 여부
- **가능(Yes)**
- 규칙 예시
  - A: 추세 강함 + 골드존 정중앙 반응 + 거래량 우수 + RR 충분
  - B: 핵심 조건 충족, 부가 조건 일부 미달
  - C: 최소 조건만 충족
- 구현: `score` 정수 기반 후 `grade` 문자열로 매핑, `label.new` 표시

## 6.4 디버깅용 plot/label 항목
- 권장 디버깅 출력
  - `trendLong`, `trendShort` 상태 plotchar
  - 최근 pivot 가격/인덱스
  - 계산된 fib50/fib618/SL/TP1/TP2
  - 제외 사유 코드(예: 1=RR미달, 2=횡보, 3=시간필터)
- 옵션화
  - `debugMode` input(bool)로 on/off

## 7) 최적화 대상 변수

## 7.1 바꿔볼 변수(최적화 대상)
- 추세 필터
  - `emaFastLen`, `emaSlowLen`, `adxMin`
- 구조/진입
  - `pivotLeft/right`, `entryTolerancePct`, `fibEntryMain`(0.5 vs 0.618)
- 리스크/청산
  - `slAtrMult`, `tp1RR`, `tp2RR`, `trailAtrMult`, `tp1QtyPct`
- 필터
  - `volMinRatio`, `minAtrPct`, `minRR`

## 7.2 고정할 변수
- 시장/종목 세트
- 테스트 기간(IS/OOS 분리)
- 수수료/슬리피지 가정
- 진입 로직의 큰 구조(추세→스윙→피보→트리거→RR검증)
- 포지션 사이징 정책(초기 버전 고정)

## 7.3 과최적화 방지 원칙
- 한 번에 1개 변수군만 조정(추세군/진입군/청산군 분리)
- OOS 성능 하락 시 즉시 파라미터 롤백
- 파라미터 민감도 확인
  - 최적점 1개가 아닌 “완만한 plateau” 구간 채택
- 최소 거래 수 조건 유지(표본 부족 파라미터 폐기)
- Walk-forward에서 70% 이상 구간 일관성 미달 시 폐기
